    🏥 신약 데이터에서 후보 찾기 — 탐색 성능 비교¶

    Part 4: 탐색 알고리즘 — 원하는 데이터를 효율적으로 찾는 방법

    🎯 이 장에서 배우는 것¶

    • 순차 탐색과 이진 탐색의 비교 횟수를 동일 데이터로 실험하여 비교할 수 있다
    • 데이터 크기가 커질수록 이진 탐색이 순차 탐색보다 효율적인 이유를 수치로 설명할 수 있다
    • 실생활 상황에서 어떤 탐색 방법이 적합한지 판단 기준을 제시할 수 있다
    • 빅오 표기법으로 두 알고리즘의 성능 차이를 표현할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 💭

    여러분이 제약회사 연구원이라고 상상해보세요. 신약 개발을 위해 100만 개의 화합물 데이터베이스에서 특정 화합물을 찾아야 합니다. 한 번 비교하는 데 0.001초가 걸린다면, 최악의 경우 얼마나 걸릴까요?

    순차 탐색으로 100만 개를 모두 확인한다면 약 17분이 걸립니다. 하지만 이진 탐색을 사용하면 0.02초 만에 찾을 수 있습니다. 같은 문제인데 5만 배 이상 차이가 납니다!

    실제로 구글 검색, 온라인 쇼핑몰의 상품 검색, 병원 진료 기록 조회 등 우리가 매일 사용하는 서비스들은 모두 효율적인 탐색 알고리즘 덕분에 빠르게 작동합니다. 이번 시간에는 왜 이런 차이가 발생하는지 직접 실험하고 분석해보겠습니다.

    📚 핵심 개념¶

    개념 1: 탐색 성능을 측정하는 방법¶

    🎯 비유로 시작하기

    시험 점수를 비교할 때 "누가 더 잘 봤나?"를 어떻게 판단하나요? 점수라는 기준이 있기 때문에 비교가 가능합니다. 알고리즘도 마찬가지입니다.

    📖 정확한 정의

    탐색 알고리즘의 성능은 비교 횟수로 측정합니다. 원하는 데이터를 찾기 위해 몇 번이나 "이게 맞나?" 확인했는지 세는 것이죠.

    성능 측정의 세 가지 경우 - 최선의 경우(Best Case): 운 좋게 바로 찾는 경우 - 최악의 경우(Worst Case): 가장 오래 걸리는 경우 - 평균의 경우(Average Case): 일반적인 상황

    💡 알아보기

    알고리즘 성능 분석에서는 주로 최악의 경우를 기준으로 합니다. 왜냐하면 "최소한 이 정도 시간 안에는 끝난다"를 보장할 수 있기 때문입니다.

    개념 2: 순차 탐색 vs 이진 탐색 성능 비교¶

    🎯 비유로 시작하기

    순차 탐색: 출석부에서 이름을 찾을 때 1번부터 차례대로 확인하는 것 이진 탐색: 사전에서 단어를 찾을 때 중간을 펼쳐서 앞뒤로 범위를 좁히는 것

    📖 성능 비교표

    데이터 개수별 최대 비교 횟수를 살펴봅시다:

    graph LR subgraph 순차탐색["순차 탐색 O(n)"] A1["10개 → 10회"] A2["100개 → 100회"] A3["1,000개 → 1,000회"] A4["1,000,000개 → 1,000,000회"] end subgraph 이진탐색["이진 탐색 O(log n)"] B1["10개 → 4회"] B2["100개 → 7회"] B3["1,000개 → 10회"] B4["1,000,000개 → 20회"] end

    📊 수치로 확인하기

    • 10개 데이터: 순차 10회 vs 이진 4회 (2.5배 차이)
    • 100개 데이터: 순차 100회 vs 이진 7회 (14배 차이)
    • 1,000개 데이터: 순차 1,000회 vs 이진 10회 (100배 차이)
    • 1,000,000개 데이터: 순차 1,000,000회 vs 이진 20회 (50,000배 차이!)

    🤔 생각해보기

    데이터가 10배 늘어날 때, 순차 탐색의 비교 횟수는 어떻게 변하나요? 이진 탐색은요?

    개념 3: 빅오 표기법으로 성능 표현하기¶

    🎯 비유로 시작하기

    "서울에서 부산까지 얼마나 걸려요?"라고 물으면 "약 4시간이요"라고 대답합니다. 정확히 4시간 23분 15초가 아니라 대략적인 규모로 말하는 것이죠. 빅오 표기법도 마찬가지입니다.

    📖 정확한 정의

    빅오 표기법(Big-O notation): 데이터 개수 n에 따라 연산 횟수가 어떤 비율로 증가하는지 나타내는 방식

    • O(n): n에 비례하여 증가 (선형)
    • O(log n): 매우 천천히 증가 (로그)

    예시로 확인하기

    graph TD subgraph 성능비교["알고리즘 성능 비교"] SEQ["순차 탐색<br/>O(n)<br/>n이 2배 → 시간도 2배"] BIN["이진 탐색<br/>O(log n)<br/>n이 2배 → 시간은 +1회만"] end SEQ --> |"데이터 많을수록"| SLOW["급격히 느려짐"] BIN --> |"데이터 많아도"| FAST["거의 일정"]

    💡 알아보기: log₂의 의미

    log₂(n)은 "2를 몇 번 곱해야 n이 되는가?"입니다. - log₂(8) = 3 (2×2×2 = 8) - log₂(1024) = 10 (2를 10번 곱하면 1024)

    이진 탐색은 매번 범위를 절반으로 줄이므로, 1024개 데이터에서 최대 10번 비교로 찾을 수 있습니다!

    개념 4: 탐색 알고리즘 선택 기준¶

    📖 정확한 정의

    탐색 알고리즘 선택 시 고려해야 할 핵심 요소:

    1. 데이터가 정렬되어 있는가? - 정렬 안 됨 → 순차 탐색만 가능 - 정렬 됨 → 이진 탐색 사용 가능

    2. 데이터 크기는 얼마인가? - 소규모(수십 개) → 순차 탐색도 충분 - 대규모(수천 개 이상) → 이진 탐색 권장

    3. 정렬 비용을 감당할 수 있는가? - 한 번 정렬 후 여러 번 검색 → 정렬 후 이진 탐색 - 한 번만 검색 → 순차 탐색이 나을 수도

    flowchart TD START["데이터에서 값을 찾아야 함"] --> Q1{"데이터가<br/>정렬되어 있나요?"} Q1 -->|"아니오"| Q2{"정렬할<br/>여유가 있나요?"} Q1 -->|"예"| Q3{"데이터가<br/>1000개 이상인가요?"} Q2 -->|"아니오"| SEQ1["순차 탐색 사용"] Q2 -->|"예"| SORT["먼저 정렬 실행"] --> Q3 Q3 -->|"예"| BIN["이진 탐색 사용"] Q3 -->|"아니오"| SEQ2["순차 탐색도 OK"]

    🔨 따라하기: 신약 후보 탐색 실험¶

    제약회사 데이터베이스에서 특정 화합물을 찾는 시뮬레이션을 해봅시다.

    Step 1: 실험 데이터 준비하기¶

    # 화합물 ID 데이터 생성 (이미 정렬된 상태)
def create_compound_data(size):
    """화합물 ID 리스트 생성"""
    return [f"COMP-{str(i).zfill(6)}" for i in range(1, size + 1)]

# 10개, 100개, 1000개 데이터 생성
data_10 = create_compound_data(10)
data_100 = create_compound_data(100)
data_1000 = create_compound_data(1000)

print("10개 데이터 샘플:", data_10[:5], "...")
print("데이터는 정렬되어 있습니다!")

    실행 결과: 

    10개 데이터 샘플: ['COMP-000001', 'COMP-000002', 'COMP-000003', 'COMP-000004', 'COMP-000005'] ...
데이터는 정렬되어 있습니다!

    Step 2: 비교 횟수를 세는 탐색 함수 만들기¶

    def sequential_search_count(data, target):
    """순차 탐색 - 비교 횟수 반환"""
    count = 0
    for i in range(len(data)):
        count += 1  # 비교할 때마다 카운트
        if data[i] == target:
            return count, i  # (비교 횟수, 찾은 위치)
    return count, -1  # 못 찾음

def binary_search_count(data, target):
    """이진 탐색 - 비교 횟수 반환"""
    count = 0
    low = 0
    high = len(data) - 1

    while low <= high:
        count += 1  # 비교할 때마다 카운트
        mid = (low + high) // 2

        if data[mid] == target:
            return count, mid
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1

    return count, -1

print("탐색 함수 준비 완료!")

    Step 3: 최악의 경우 실험하기¶

    # 최악의 경우: 맨 마지막 데이터 찾기
print("=== 최악의 경우 비교 (맨 마지막 데이터 탐색) ===\n")

for size, data in [(10, data_10), (100, data_100), (1000, data_1000)]:
    target = f"COMP-{str(size).zfill(6)}"  # 마지막 화합물

    seq_count, seq_pos = sequential_search_count(data, target)
    bin_count, bin_pos = binary_search_count(data, target)

    print(f"데이터 {size}개에서 '{target}' 찾기:")
    print(f"  순차 탐색: {seq_count}회 비교")
    print(f"  이진 탐색: {bin_count}회 비교")
    print(f"  효율 차이: 이진 탐색이 {seq_count // bin_count}배 빠름\n")

    Step 4: 100만 개 데이터로 확장 실험¶

    import math

# 대규모 데이터 시뮬레이션
sizes = [10, 100, 1000, 10000, 100000, 1000000]

print("=== 데이터 크기별 최대 비교 횟수 예측 ===\n")
print("데이터 크기 | 순차 탐색 | 이진 탐색 | 효율 차이")
print("-" * 50)

for n in sizes:
    seq_max = n  # 순차: 최악의 경우 n번
    bin_max = math.ceil(math.log2(n + 1))  # 이진: log₂(n+1) 올림

    ratio = n // bin_max if bin_max > 0 else 0
    print(f"{n:>10,}개 | {seq_max:>9,}회 | {bin_max:>9}회 | {ratio:,}배")

    📝 전체 코드¶

    """
신약 데이터에서 후보 찾기 - 탐색 성능 비교 실험
"""
import math
import time

# === 데이터 생성 ===
def create_compound_data(size):
    """화합물 ID 리스트 생성 (정렬된 상태)"""
    return [f"COMP-{str(i).zfill(6)}" for i in range(1, size + 1)]

# === 탐색 함수 (비교 횟수 포함) ===
def sequential_search_count(data, target):
    """순차 탐색 - 비교 횟수 반환"""
    count = 0
    for i in range(len(data)):
        count += 1
        if data[i] == target:
            return count, i
    return count, -1

def binary_search_count(data, target):
    """이진 탐색 - 비교 횟수 반환"""
    count = 0
    low, high = 0, len(data) - 1

    while low <= high:
        count += 1
        mid = (low + high) // 2
        if data[mid] == target:
            return count, mid
        elif data[mid] < target:
            low = mid + 1
        else:
            high = mid - 1
    return count, -1

# === 메인 실행 ===
if __name__ == "__main__":
    print("🏥 신약 후보 탐색 성능 비교 실험\n")

    # 다양한 크기의 데이터 테스트
    for size in [10, 100, 1000]:
        data = create_compound_data(size)
        target = data[-1]  # 마지막 요소 (최악의 경우)

        seq_count, _ = sequential_search_count(data, target)
        bin_count, _ = binary_search_count(data, target)

        print(f"[{size}개 데이터]")
        print(f"  순차: {seq_count}회 | 이진: {bin_count}회")
        print(f"  → 이진 탐색이 {seq_count//bin_count}배 효율적\n")

    # 이론적 비교 (100만 개)
    n = 1000000
    print(f"[{n:,}개 데이터 예측]")
    print(f"  순차: {n:,}회 | 이진: {math.ceil(math.log2(n))}회")

    기본 문제¶

    문제 1: 1024개 데이터에서 이진 탐색의 최대 비교 횟수는?

    정답 보기 **10회**입니다. log₂(1024) = 10이므로, 최대 10번의 비교로 모든 데이터를 탐색할 수 있습니다. (2¹⁰ = 1024)

    문제 2: 다음 중 순차 탐색을 사용해야 하는 상황은?

    A) 정렬된 학생 명부에서 이름 찾기 B) 정렬되지 않은 설문 응답에서 특정 답변 찾기 C) 사전에서 단어 찾기

    정답 보기 **B) 정렬되지 않은 설문 응답에서 특정 답변 찾기** 이진 탐색은 반드시 정렬된 데이터에서만 사용할 수 있습니다.

    응용 문제¶

    문제 3: 어떤 알고리즘이 O(n²) 성능을 가지고 있습니다. 데이터가 10개일 때 100ms가 걸렸다면, 100개일 때 예상 시간은?

    정답 보기 **약 10,000ms (10초)** O(n²)이므로 데이터가 10배 늘면 시간은 100배(10²) 늘어납니다. 100ms × 100 = 10,000ms

    심화 문제¶

    문제 4: 정렬되지 않은 1000개 데이터에서 특정 값을 100번 검색해야 합니다. 다음 중 더 효율적인 방법은?

    A) 순차 탐색을 100번 수행 B) 먼저 정렬(약 10,000번 비교)한 후 이진 탐색 100번

    정답 보기 **B) 정렬 후 이진 탐색** - A 방법: 1000 × 100 = 100,000번 비교 - B 방법: 10,000(정렬) + 10 × 100(이진탐색) = 11,000번 비교 **여러 번 검색할 때는 정렬 비용을 감수하고 이진 탐색을 사용하는 것이 효율적입니다.**
