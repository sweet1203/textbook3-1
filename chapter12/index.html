    🏙️ 어떤 정렬이 더 빠를까? — 빅오 표기법과 성능 비교¶

    Part 3: 정렬 알고리즘 — 데이터를 순서대로 정리하는 방법

    🎯 이 장에서 배우는 것¶

    • 빅오 표기법(O(1), O(n), O(n²))의 의미를 입력 크기와 수행 시간의 관계로 설명할 수 있다
    • 버블 정렬, 삽입 정렬, 퀵 정렬의 시간 복잡도를 비교하여 설명할 수 있다
    • 주어진 상황에서 어떤 정렬 알고리즘이 더 적합한지 판단할 수 있다
    • 데이터 크기에 따른 연산 횟수 차이를 계산할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔

    스마트시티의 교통 관제 센터에서 실시간으로 들어오는 차량 데이터를 정렬해야 합니다. 데이터가 10개일 때와 10,000개일 때, 정렬 시간은 과연 얼마나 차이가 날까요?

    우리는 이전 장에서 버블 정렬, 삽입 정렬, 퀵 정렬을 배웠습니다. 세 가지 모두 데이터를 정렬할 수 있지만, "어떤 것이 더 빠를까?"라는 질문에는 쉽게 답하기 어렵습니다.

    알고리즘의 성능을 비교하려면 공통된 기준이 필요합니다. 마치 달리기 선수들의 실력을 비교하려면 같은 거리에서 기록을 측정해야 하는 것처럼요. 이 장에서 배울 빅오 표기법은 알고리즘의 성능을 표현하는 공통 언어입니다.

    실제로 구글, 네이버 같은 검색 엔진은 수십억 개의 데이터를 다룹니다. 잘못된 알고리즘을 선택하면 검색 결과가 나오기까지 몇 시간이 걸릴 수도 있습니다. 올바른 알고리즘을 선택하면 0.1초 만에 결과를 볼 수 있고요!

    📚 핵심 개념¶

    개념 1: 알고리즘 성능이란?¶

    🎯 비유로 시작하기

    여러분이 100권의 책을 가나다순으로 정리한다고 상상해 보세요. 어떤 방법은 30분이면 끝나고, 어떤 방법은 2시간이 걸립니다. 같은 결과를 내더라도 걸리는 시간이 다르죠. 알고리즘도 마찬가지입니다.

    📖 정확한 정의

    알고리즘의 성능은 두 가지 기준으로 측정합니다.

    • 수행 시간: 알고리즘이 문제를 해결하는 데 필요한 연산 횟수
    • 기억 공간: 알고리즘 실행에 필요한 메모리 크기

    이 장에서는 수행 시간에 집중합니다. 수행 시간은 실제 시간(초, 분)보다 연산 횟수로 측정하는 것이 더 정확합니다. 왜냐하면 같은 알고리즘이라도 컴퓨터 성능에 따라 실제 시간은 달라지기 때문입니다.

    ✅ 예시로 확인

    # 예시: 리스트에서 최댓값 찾기
numbers = [3, 7, 2, 9, 5]

max_value = numbers[0]  # 연산 1회
for num in numbers:     # 5번 반복
    if num > max_value: # 비교 연산 5회
        max_value = num # 대입 연산 (최대 5회)

    이 알고리즘에서 비교 연산은 데이터 개수(5개)만큼 수행됩니다. 데이터가 100개면? 비교도 100번!

    개념 2: 빅오 표기법 (Big-O Notation)¶

    🎯 비유로 시작하기

    택배 회사의 배송 시간을 설명할 때, "서울에서 부산까지 정확히 4시간 23분 15초"라고 하지 않습니다. 대신 "약 4~5시간"이라고 말하죠. 빅오 표기법도 마찬가지로, 알고리즘의 성능을 대략적인 패턴으로 표현합니다.

    📖 정확한 정의

    빅오 표기법은 입력 크기(n)가 커질 때 수행 시간이 어떤 비율로 증가하는지 나타내는 방법입니다. 상수나 작은 항은 무시하고, 가장 빠르게 증가하는 항만 남깁니다.

    graph LR A["입력 크기 n"] --> B["수행 시간"] B --> C["O(1): 항상 일정"] B --> D["O(n): n에 비례"] B --> E["O(n²): n의 제곱에 비례"] B --> F["O(2ⁿ): 기하급수적 증가"]

    ✅ 주요 빅오 표기법 정리

    • O(1) - 상수 시간: 입력 크기와 관계없이 항상 같은 시간. 예) 배열의 첫 번째 요소 접근
    • O(n) - 선형 시간: 입력이 2배가 되면 시간도 2배. 예) 리스트 전체 순회
    • O(n²) - 이차 시간: 입력이 2배가 되면 시간은 4배. 예) 이중 반복문
    • O(2ⁿ) - 지수 시간: 입력이 1 증가하면 시간이 2배. 예) 모든 부분집합 구하기

    ✅ 성능 비교 그래프

    graph TB subgraph "입력 크기 증가에 따른 수행 시간" direction LR N10["n=10"] N100["n=100"] N1000["n=1000"] end subgraph "O(1)" A1["1"] --> A2["1"] --> A3["1"] end subgraph "O(n)" B1["10"] --> B2["100"] --> B3["1,000"] end subgraph "O(n²)" C1["100"] --> C2["10,000"] --> C3["1,000,000"] end

    알아보기 📌

    왜 상수는 무시할까요? n이 매우 커지면 상수의 영향은 미미해집니다. 예를 들어 3n²과 n²은 n=1000일 때 각각 3,000,000과 1,000,000이지만, 둘 다 "백만 단위"라는 점에서 같은 수준입니다.

    개념 3: 정렬 알고리즘의 시간 복잡도¶

    🎯 비유로 시작하기

    세 명의 도서관 사서가 있습니다. A는 꼼꼼하지만 느리고, B는 상황에 따라 속도가 다르며, C는 대부분 빠르지만 가끔 느립니다. 정렬 알고리즘도 각자의 특성이 있습니다.

    📖 정확한 정의와 비교

    flowchart TB subgraph 버블정렬["버블 정렬"] B1["항상 O(n²)"] B2["인접 요소 비교·교환"] B3["단순하지만 느림"] end subgraph 삽입정렬["삽입 정렬"] I1["최선 O(n), 최악 O(n²)"] I2["정렬된 위치에 삽입"] I3["거의 정렬된 데이터에 유리"] end subgraph 퀵정렬["퀵 정렬"] Q1["평균적으로 빠름"] Q2["피벗 기준 분할"] Q3["대용량 데이터에 적합"] end

    ✅ 각 정렬의 연산 횟수 계산

    • 버블 정렬: (n-1) + (n-2) + ... + 1 = n(n-1)/2 ≈ O(n²)
    • 삽입 정렬: 최악의 경우 위와 동일하게 O(n²), 이미 정렬된 경우 O(n)
    • 퀵 정렬: 평균적으로 O(n log n), 최악의 경우 O(n²)

    개념 4: 상황에 맞는 알고리즘 선택¶

    🎯 비유로 시작하기

    요리할 때 재료에 따라 도구가 달라집니다. 양파를 썰 때는 칼을, 밀가루를 섞을 때는 거품기를 쓰죠. 알고리즘도 상황에 맞게 선택해야 합니다.

    📖 선택 기준

    flowchart TD Start["데이터 특성 파악"] --> Q1{"데이터 크기가 작은가?<br/>n < 50"} Q1 -->|Yes| A1["아무 알고리즘이나 OK<br/>성능 차이 미미"] Q1 -->|No| Q2{"데이터가 거의 정렬되어 있는가?"} Q2 -->|Yes| A2["삽입 정렬 추천<br/>O(n)에 가까움"] Q2 -->|No| Q3{"대용량 데이터인가?"} Q3 -->|Yes| A3["퀵 정렬 추천<br/>평균 O(n log n)"] Q3 -->|No| A4["버블 정렬도 가능<br/>구현이 단순"]

    ✅ 스마트시티 사례로 이해하기

    교통 관제 센터에서 차량 속도 데이터를 정렬해야 합니다.

    • 실시간 모니터링(10대): 어떤 알고리즘이든 빠름 → 구현 쉬운 버블 정렬 OK
    • 1시간 통계(1,000대): 삽입 정렬이나 퀵 정렬 권장
    • 하루 전체 분석(100,000대): 반드시 퀵 정렬처럼 효율적인 알고리즘 필요

    🔨 따라하기¶

    Step 1: 빅오 표기법 체감하기¶

    먼저 간단한 코드로 O(1), O(n), O(n²)의 차이를 직접 확인해 봅시다.

    # O(1) - 상수 시간: 입력 크기와 무관
def get_first(data):
    return data[0]  # 항상 1번의 연산

# O(n) - 선형 시간: 입력 크기에 비례
def find_sum(data):
    total = 0
    for num in data:  # n번 반복
        total += num
    return total

# O(n²) - 이차 시간: 입력 크기의 제곱에 비례
def find_pairs(data):
    count = 0
    for i in data:       # n번 반복
        for j in data:   # 각각 n번 반복
            count += 1
    return count

    Step 2: 연산 횟수 측정하기¶

    실제로 연산 횟수가 어떻게 달라지는지 확인해 봅시다.

    def bubble_sort_count(arr):
    """버블 정렬의 비교 연산 횟수를 세는 함수"""
    n = len(arr)
    count = 0
    data = arr.copy()  # 원본 보존

    for i in range(n - 1):
        for j in range(n - 1 - i):
            count += 1  # 비교 연산 카운트
            if data[j] > data[j + 1]:
                data[j], data[j + 1] = data[j + 1], data[j]

    return count, data

# 테스트
test_data = [5, 3, 8, 1, 9, 2]
operations, sorted_data = bubble_sort_count(test_data)
print(f"데이터 {len(test_data)}개 정렬")
print(f"비교 연산 횟수: {operations}")
print(f"정렬 결과: {sorted_data}")

    Step 3: 데이터 크기별 비교 실험¶

    데이터 크기를 바꿔가며 연산 횟수가 어떻게 변하는지 관찰합니다.

    import random

def count_operations(n):
    """n개 데이터의 버블 정렬 연산 횟수"""
    data = list(range(n))
    random.shuffle(data)
    count, _ = bubble_sort_count(data)
    return count

# 다양한 크기로 테스트
sizes = [10, 50, 100, 200]
print("=== 버블 정렬 연산 횟수 비교 ===")
for size in sizes:
    ops = count_operations(size)
    theoretical = size * (size - 1) // 2  # n(n-1)/2
    print(f"n={size:3d}: 실제 {ops:5d}회, 이론값 {theoretical:5d}회")

    Step 4: 삽입 정렬과 비교하기¶

    삽입 정렬의 연산 횟수도 측정하여 버블 정렬과 비교합니다.

    def insertion_sort_count(arr):
    """삽입 정렬의 비교 연산 횟수를 세는 함수"""
    data = arr.copy()
    count = 0

    for i in range(1, len(data)):
        key = data[i]
        j = i - 1
        while j >= 0 and data[j] > key:
            count += 1  # 비교 연산 카운트
            data[j + 1] = data[j]
            j -= 1
        count += 1  # while 조건 검사도 비교
        data[j + 1] = key

    return count, data

# 무작위 데이터로 비교
test = [random.randint(1, 100) for _ in range(20)]
bubble_ops, _ = bubble_sort_count(test)
insert_ops, _ = insertion_sort_count(test)

print(f"데이터 20개 정렬 비교")
print(f"버블 정렬: {bubble_ops}회")
print(f"삽입 정렬: {insert_ops}회")

    Step 5: 거의 정렬된 데이터에서 테스트¶

almost_sorted = list(range(1, 21))  # [1, 2, 3, ..., 20]

    Step 6: 스마트시티 시나리오 적용¶

    교통 데이터 규모에 따른 예상 수행 시간을 계산합니다.

    def estimate_time(n, algorithm):
    """
    알고리즘별 예상 연산 횟수 계산
    (1회 연산 = 0.000001초로 가정)
    """
    if algorithm == "bubble":
        operations = n * (n - 1) // 2
    elif algorithm == "insertion_best":
        operations = n - 1
    elif algorithm == "insertion_worst":
        operations = n * (n - 1) // 2

    time_sec = operations * 0.000001
    return operations, time_sec

# 스마트시티 교통 데이터 시나리오
scenarios = [
    ("실시간 모니터링", 100),
    ("1시간 통계", 1000),
    ("하루 전체", 100000)
]

print("=== 스마트시티 교통 데이터 정렬 예상 시간 ===")
for name, n in scenarios:
    ops, time = estimate_time(n, "bubble")
    print(f"\n{name} (데이터 {n:,}개)")
    print(f"  버블 정렬: {ops:,}회 연산, 약 {time:.4f}초")

    📝 전체 코드¶

    아래는 이 장에서 배운 내용을 종합한 실습 코드입니다.

    """
빅오 표기법과 정렬 알고리즘 성능 비교 실습
"""
import random

# ===== 정렬 알고리즘 (연산 횟수 측정 포함) =====
def bubble_sort_count(arr):
    """버블 정렬 - 비교 횟수 반환"""
    data = arr.copy()
    n = len(data)
    count = 0

    for i in range(n - 1):
        for j in range(n - 1 - i):
            count += 1
            if data[j] > data[j + 1]:
                data[j], data[j + 1] = data[j + 1], data[j]
    return count, data

def insertion_sort_count(arr):
    """삽입 정렬 - 비교 횟수 반환"""
    data = arr.copy()
    count = 0

    for i in range(1, len(data)):
        key = data[i]
        j = i - 1
        while j >= 0 and data[j] > key:
            count += 1
            data[j + 1] = data[j]
            j -= 1
        count += 1
        data[j + 1] = key
    return count, data

# ===== 성능 비교 실험 =====
def compare_algorithms(sizes):
    """다양한 크기의 데이터로 알고리즘 비교"""
    print("=" * 50)
    print("정렬 알고리즘 성능 비교 (비교 연산 횟수)")
    print("=" * 50)

    for n in sizes:
        # 무작위 데이터 생성
        data = [random.randint(1, 1000) for _ in range(n)]

        bubble_ops, _ = bubble_sort_count(data)
        insert_ops, _ = insertion_sort_count(data)

        print(f"\n데이터 크기: {n}개")
        print(f"  버블 정렬: {bubble_ops:,}회")
        print(f"  삽입 정렬: {insert_ops:,}회")
        print(f"  이론값 O(n²): {n*n:,}")

# ===== 실행 =====
if __name__ == "__main__":
    test_sizes = [10, 50, 100, 200]
    compare_algorithms(test_sizes)

    # 거의 정렬된 데이터 테스트
    print("\n" + "=" * 50)
    print("거의 정렬된 데이터에서의 비교")
    print("=" * 50)

    almost = list(range(100))
    almost[10], almost[11] = almost[11], almost[10]  # 2개만 교환

    b_ops, _ = bubble_sort_count(almost)
    i_ops, _ = insertion_sort_count(almost)

    print(f"버블 정렬: {b_ops}회")
    print(f"삽입 정렬: {i_ops}회 (훨씬 적음!)")

    ❌ 실수 2: "빅오가 같으면 성능이 같다"

    # O(n²)인 두 알고리즘이라도
# 실제 연산 횟수는 다를 수 있습니다.

# 버블 정렬: 항상 n(n-1)/2회 비교
# 삽입 정렬: 최선 n-1회, 최악 n(n-1)/2회

# 같은 O(n²)라도 상수 계수나 최선/최악이 다릅니다!

    ✅ 올바른 이해: 빅오는 증가 패턴을 나타내며, 정확한 횟수는 아닙니다.

    ❌ 실수 3: "데이터가 적으면 빠른 알고리즘이 필요 없다"

    # n=10일 때 연산 횟수
# O(n²): 100회
# O(n): 10회
# 둘 다 순식간에 끝남 (차이 못 느낌)

# 하지만 n=10000이면?
# O(n²): 100,000,000회 (1억!)
# O(n): 10,000회
# 엄청난 차이!

    ✅ 올바른 이해: 작은 데이터에서는 차이가 없어 보여도, 확장성을 고려해야 합니다.

    심화 문제¶

    4. 도전! 연산 횟수 계산하기

    O(n²) 알고리즘으로 정렬할 때: - 데이터 100개: 약 __회 - 데이터 1000개: 약 _회 - 1000개는 100개보다 약 ___배 더 많은 연산이 필요합니다.

    정답 확인하기 **1번 정답**: O, X, O, O - 두 번째가 X인 이유: n이 매우 작을 때(예: n=1)는 O(n²)도 빠를 수 있습니다. "항상"은 틀린 표현입니다. **2번 정답**: 10,000회 (100 × 100 = 10,000) **3번 정답**: **삽입 정렬**을 추천합니다. - 이유: 기존 데이터가 이미 정렬되어 있고, 새 데이터 1개만 올바른 위치에 삽입하면 됩니다. 이 경우 삽입 정렬은 O(n)에 가까운 성능을 보입니다. **4번 정답**: - 100개: 약 10,000회 (100²) - 1000개: 약 1,000,000회 (1000²) - 1000개는 100개보다 약 **100배** 더 많은 연산이 필요합니다.

    import time
import random

def measure_time(sort_func, data):
    start = time.time()
    sort_func(data.copy())
    end = time.time()
    return end - start

# 다양한 크기로 테스트해 보세요

for n in sizes:
    test_data = [random.randint(1, 10000) for _ in range(n)]
    bubble_time = measure_time(lambda x: bubble_sort_count(x), test_data)
    print(f"n={n}: {bubble_time:.4f}초")
