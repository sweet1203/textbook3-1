    알고리즘, 왜 배울까? — 세상을 바꾸는 절차의 힘¶

    🎯 이 장에서 배우는 것¶

    • 알고리즘의 의미를 일상생활 사례를 통해 설명할 수 있다
    • 알고리즘이 사회문제 해결에 활용되는 실제 사례를 3가지 이상 제시할 수 있다
    • 이 단원에서 학습할 내용의 전체 흐름을 파악할 수 있다

    📚 핵심 개념¶

    🤔 생각해보기: 내비게이션은 어떻게 최단 경로를 찾을까?¶

    여러분이 처음 가는 장소를 찾아갈 때 내비게이션을 사용해 본 적이 있나요? 내비게이션에 목적지를 입력하면 몇 초 만에 "이 경로로 가세요"라고 안내해 줍니다.

    잠깐, 이상하지 않나요? 서울에서 부산까지 가는 길은 수천, 수만 가지인데, 어떻게 그렇게 빠르게 "가장 빠른 길"을 찾아낼까요?

    비밀은 바로 알고리즘에 있습니다.

    개념 1: 알고리즘이란?¶

    비유로 시작해 볼까요?

    알고리즘은 마치 요리 레시피와 같아요. 라면을 끓이려면:

    1. 물 550ml를 냄비에 붓는다
    2. 물이 끓으면 면과 스프를 넣는다
    3. 4분 30초 동안 끓인다
    4. 그릇에 담아 완성한다

    이처럼 문제를 해결하기 위해 정해진 순서대로 수행하는 절차가 바로 알고리즘입니다.

    정확한 정의

    알고리즘(Algorithm): 주어진 문제를 해결하기 위한 일련의 단계적 절차나 방법

    예시로 확인

    우리는 이미 매일 알고리즘을 따르고 있어요:

    • 아침 등교 알고리즘: 알람 끄기 → 씻기 → 옷 입기 → 아침 먹기 → 집 나서기
    • 자판기 음료 구매 알고리즘: 동전 투입 → 음료 선택 → 버튼 누르기 → 음료 수령
    • 도서관 책 찾기 알고리즘: 검색대에서 책 위치 확인 → 해당 서가 이동 → 책 찾기

    개념 2: 왜 알고리즘을 배울까?¶

    컴퓨터는 스스로 생각하지 못합니다. 우리가 정확한 절차를 알려줘야만 문제를 해결할 수 있어요.

    flowchart LR A[복잡한 문제] --> B[알고리즘 설계] B --> C[컴퓨터에게 전달] C --> D[자동으로 해결!]

    좋은 알고리즘을 설계하면: - 빠르게 문제를 해결할 수 있어요 - 정확하게 원하는 결과를 얻을 수 있어요 - 반복적인 일을 컴퓨터에게 맡길 수 있어요

    개념 3: 알고리즘이 바꾸는 세상¶

    알고리즘은 단순한 컴퓨터 용어가 아닙니다. 실제로 우리 사회의 중요한 문제들을 해결하고 있어요.

    🏥 사례 1: 응급실 환자 분류 (트리아지)

    응급실에 환자 10명이 동시에 도착했습니다. 누구를 먼저 치료해야 할까요? 먼저 온 순서대로? 아닙니다!

    정렬 알고리즘을 활용해 환자의 위급도를 기준으로 순서를 정합니다. 심장마비 환자는 가벼운 찰과상 환자보다 먼저 치료받아야 하니까요.

    🔥 사례 2: 재난 대피 경로 안내

    화재가 발생했을 때, 모든 사람이 같은 출구로 몰리면 어떻게 될까요?

    탐색 알고리즘이 각 사람의 위치에서 가장 가깝고 안전한 출구를 찾아 분산 대피시킵니다.

    ♻️ 사례 3: 재활용 쓰레기 분류

    수천 톤의 재활용 쓰레기를 사람이 일일이 분류한다면?

    정렬 알고리즘으로 플라스틱, 유리, 종이를 자동 분류하여 재활용률을 높입니다.

    🔨 따라하기: 내가 매일 따르는 알고리즘 찾기¶

    Step 1: 일상 속 절차 떠올리기¶

    오늘 아침부터 지금까지 여러분이 했던 일 중 하나를 골라보세요.

    예시: "학교 사물함에서 책 꺼내기"

    Step 2: 단계별로 분해하기¶

    그 행동을 누구나 따라 할 수 있도록 단계별로 적어봅시다.

    1. 사물함 앞으로 간다
2. 자물쇠 비밀번호를 입력한다
3. 사물함 문을 연다
4. 필요한 책을 찾는다
5. 책을 꺼낸다
6. 사물함 문을 닫는다

    Step 3: 알고리즘의 특징 확인하기¶

    여러분이 작성한 절차가 다음 조건을 만족하는지 확인해 보세요:

    • ✓ 명확성: 각 단계가 모호하지 않고 명확한가?
    • ✓ 순서: 단계의 순서가 정해져 있는가?
    • ✓ 유한성: 언젠가는 끝나는가?

    세 가지를 모두 만족하면, 축하합니다! 여러분은 방금 알고리즘을 설계한 거예요. 🎉

    🗺️ 이 단원의 학습 로드맵¶

    앞으로 우리는 다음 순서로 알고리즘을 배워갈 거예요:

    flowchart TD A["1️⃣ 문제 분해와 모델링<br/>복잡한 문제를 작게 나누기"] B["2️⃣ 정렬 알고리즘<br/>데이터를 순서대로 배열하기"] C["3️⃣ 탐색 알고리즘<br/>원하는 데이터를 빠르게 찾기"] A --> B --> C

    1️⃣ 문제 분해와 모델링 - 복잡한 문제를 해결 가능한 작은 문제로 나눕니다 - 핵심 요소만 추출하는 추상화를 배웁니다

    2️⃣ 정렬 알고리즘 - 버블 정렬, 삽입 정렬, 퀵 정렬을 배웁니다 - "어떤 방법이 더 빠를까?" 성능을 비교합니다

    3️⃣ 탐색 알고리즘 - 순차 탐색, 이진 탐색을 배웁니다 - 정렬된 데이터가 왜 중요한지 깨닫습니다

    ⚠️ 주의할 점¶

    1. 알고리즘 ≠ 프로그래밍 언어

    알고리즘은 "절차"이고, 프로그래밍 언어는 그 절차를 컴퓨터에게 전달하는 "도구"입니다. 요리 레시피(알고리즘)와 요리 도구(프로그래밍 언어)의 관계와 같아요.

    2. 같은 문제, 여러 알고리즘

    하나의 문제를 해결하는 알고리즘은 여러 가지가 있을 수 있어요. 그래서 "어떤 알고리즘이 더 효율적인가?"를 판단하는 능력이 중요합니다.

    ✅ 점검하기¶

    1. 다음 설명이 맞으면 O, 틀리면 X를 표시하세요.

    (1) 알고리즘은 반드시 컴퓨터로만 실행해야 한다. ( )

    (2) 라면 끓이는 순서도 알고리즘이라고 할 수 있다. ( )

    (3) 하나의 문제에는 반드시 하나의 알고리즘만 존재한다. ( )

    정답 확인 (1) **X** - 알고리즘은 문제 해결 절차이므로, 사람이 직접 수행할 수도 있습니다. (2) **O** - 명확한 단계와 순서가 있는 절차는 모두 알고리즘입니다. (3) **X** - 같은 문제를 해결하는 알고리즘은 여러 가지가 있을 수 있습니다.

    2. 알고리즘이 활용되는 실생활 사례를 3가지 적어보세요.

    예시 답안 확인 - 검색 엔진이 검색 결과를 순서대로 보여주는 것 - 음악 앱이 내 취향에 맞는 노래를 추천해 주는 것 - 배달 앱이 예상 배달 시간을 계산하는 것 - 신호등이 교통량에 따라 신호를 조절하는 것

    3. "내가 매일 따르는 알고리즘"을 3가지 찾아 각각 5단계 이내로 적어보세요.

    작성 예시 확인 **예시 1: 손 씻기 알고리즘** 1. 수도꼭지를 연다 2. 손에 물을 적신다 3. 비누로 거품을 낸다 4. 30초간 문지른다 5. 물로 헹구고 수도꼭지를 잠근다 **예시 2: 버스 타기 알고리즘** 1. 버스 정류장에서 기다린다 2. 원하는 버스가 오면 손을 든다 3. 버스에 탑승한다 4. 카드를 태그한다 5. 빈 자리에 앉거나 손잡이를 잡는다

    🔗 다음 장 미리보기¶

    다음 시간에는 "문제를 어떻게 작게 나눌까?"를 배웁니다.

    복잡해 보이는 문제도 잘게 쪼개면 해결할 수 있어요. 예를 들어 "학교 축제 준비"라는 큰 문제를 "장소 섭외", "프로그램 기획", "홍보" 등으로 나누는 것처럼요.

    이렇게 문제를 분해하고, 핵심만 남기는 추상화와 모델링을 함께 알아볼 거예요!

    💡 정리하기

    오늘 우리는 알고리즘이 "문제를 해결하는 단계적 절차"라는 것을 배웠습니다. 내비게이션의 최단 경로 찾기, 응급실 환자 분류, 재난 대피 안내 등 알고리즘은 이미 우리 생활 곳곳에서 사회 문제를 해결하고 있어요. 앞으로 문제 분해 → 정렬 → 탐색의 순서로 알고리즘의 세계를 탐험해 봅시다!
