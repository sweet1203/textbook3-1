    🏙️ 스마트시티 교통 데이터 — 퀵 정렬과 분할 정복¶

    Part 3: 정렬 알고리즘 — 데이터를 순서대로 정리하는 방법

    🎯 이 장에서 배우는 것¶

    • 분할 정복 전략의 개념을 설명할 수 있다
    • 퀵 정렬에서 피벗의 역할을 이해하고 설명할 수 있다
    • 주어진 데이터에 대해 퀵 정렬의 분할 과정을 손으로 직접 수행할 수 있다
    • 퀵 정렬의 성능이 피벗 선택에 따라 달라지는 이유를 설명할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔

    여러분이 스마트시티 교통관제센터에서 일한다고 상상해보세요. 서울시에는 약 3,000개의 교차로가 있고, 각 교차로의 실시간 교통량 데이터가 매분 수집됩니다. "가장 혼잡한 교차로 10곳을 찾아주세요!"라는 요청이 들어왔을 때, 이 데이터를 어떻게 정렬하시겠어요?

    앞서 배운 버블 정렬로 3,000개의 데이터를 정렬한다면 최대 약 900만 번의 비교가 필요합니다. 컴퓨터가 빠르다고 해도 실시간 처리에는 부담이 됩니다.

    하지만 이번에 배울 퀵 정렬을 사용하면? 평균적으로 약 3만 5천 번의 비교만으로 정렬이 끝납니다. 무려 250배 이상 빨라지는 것이죠!

    퀵 정렬의 비밀은 바로 "분할 정복"이라는 전략에 있습니다. 큰 문제를 작은 문제로 쪼개서 해결하는 이 전략은 정렬뿐 아니라 검색, 게임 AI, 이미지 처리 등 컴퓨터 과학 전반에서 활용됩니다.

    📚 핵심 개념¶

    개념 1: 분할 정복 (Divide and Conquer)¶

    🍕 피자로 이해하는 분할 정복¶

    8조각짜리 대형 피자를 혼자 다 먹기는 부담스럽습니다. 하지만 4명이서 2조각씩 나눠 먹으면? 훨씬 수월하죠!

    분할 정복도 마찬가지입니다. 큰 문제를 한 번에 해결하려 하지 않고, 작은 문제로 나눠서 각각 해결한 뒤 결과를 합칩니다.

    📖 정확한 정의¶

    분할 정복(Divide and Conquer)은 다음 세 단계로 문제를 해결하는 알고리즘 설계 전략입니다:

    1단계 - 분할(Divide): 문제를 더 작은 부분 문제로 나눕니다

    2단계 - 정복(Conquer): 각 부분 문제를 해결합니다

    3단계 - 결합(Combine): 부분 문제의 해답을 모아 전체 해답을 만듭니다

    ✅ 예시로 확인¶

    운동회에서 400명 학생의 달리기 기록을 정렬해야 한다고 합시다.

    일반적 방법: 400명 전체를 한꺼번에 비교하며 정렬

    분할 정복 방법: 1. 100명씩 4개 그룹으로 나눔 (분할) 2. 각 그룹 내에서 정렬 (정복) 3. 정렬된 4개 그룹을 합쳐서 최종 순위 결정 (결합)

    flowchart TD A[400명 전체] --> B[100명 그룹A] A --> C[100명 그룹B] A --> D[100명 그룹C] A --> E[100명 그룹D] B --> F[그룹A 정렬완료] C --> G[그룹B 정렬완료] D --> H[그룹C 정렬완료] E --> I[그룹D 정렬완료] F --> J[최종 정렬 결과] G --> J H --> J I --> J

    개념 2: 피벗 (Pivot)¶

    ⚖️ 저울추로 이해하는 피벗¶

    시장에서 과일을 무게별로 분류한다고 상상해보세요. 저울 한쪽에 "기준추 500g"을 올려놓고, 과일을 하나씩 올려봅니다. 500g보다 가벼우면 왼쪽 바구니에, 무거우면 오른쪽 바구니에 담습니다.

    이때 500g 기준추가 바로 퀵 정렬에서 말하는 피벗입니다!

    📖 정확한 정의¶

    피벗(Pivot)은 퀵 정렬에서 데이터를 두 그룹으로 나누는 기준이 되는 값입니다. 피벗보다 작은 값은 왼쪽으로, 큰 값은 오른쪽으로 이동합니다.

    ✅ 예시로 확인¶

    교통량 데이터 [85, 42, 120, 35, 90, 55, 70, 100]이 있습니다.

    피벗으로 70을 선택하면:

    70보다 작은 값 → [42, 35, 55] (왼쪽)

    피벗 → [70] (중앙)

    70보다 크거나 같은 값 → [85, 120, 90, 100] (오른쪽)

    한 번의 분할로 70은 자기 자리를 찾았습니다!

    개념 3: 퀵 정렬의 작동 원리¶

    🎯 퀵 정렬의 3단계¶

    퀵 정렬은 분할 정복 전략을 정렬에 적용한 알고리즘입니다.

    Step 1 - 피벗 선택: 리스트에서 하나의 요소를 피벗으로 선택합니다

    Step 2 - 분할: 피벗을 기준으로 작은 값은 왼쪽, 큰 값은 오른쪽으로 나눕니다

    Step 3 - 재귀: 왼쪽과 오른쪽 부분 리스트에 대해 같은 과정을 반복합니다

    flowchart LR A[피벗 선택] --> B[분할] B --> C{부분 리스트<br>크기가 1 이하?} C -->|아니오| A C -->|예| D[정렬 완료!]

    📖 재귀(Recursion)란?¶

    알아보기 📗

    재귀는 함수가 자기 자신을 다시 호출하는 것입니다. 러시아 인형 마트료시카처럼, 인형 안에 또 인형이 있고, 그 안에 또 인형이 있는 구조와 비슷합니다. 퀵 정렬에서는 "큰 리스트 정렬 = 작은 리스트 정렬 + 피벗 + 작은 리스트 정렬"로 문제를 계속 쪼갭니다.

    개념 4: 피벗 선택과 성능¶

    🎲 피벗 선택이 중요한 이유¶

    퀵 정렬의 성능은 피벗을 어떻게 선택하느냐에 크게 좌우됩니다.

    좋은 피벗: 데이터를 절반씩 균등하게 나누는 값

    나쁜 피벗: 한쪽으로 치우치게 나누는 값 (최솟값이나 최댓값)

    비교: 좋은 피벗 vs 나쁜 피벗¶

    좋은 경우 - 중앙값이 피벗일 때 - 매번 절반씩 나뉨 - 분할 횟수가 적음 - 빠른 정렬 완료

    나쁜 경우 - 최솟값이 피벗일 때 - 한쪽에 모든 데이터 몰림 - 분할 횟수가 많음 - 버블 정렬만큼 느려질 수 있음

    flowchart TD subgraph 좋은피벗[좋은 피벗 선택] A1[8개 데이터] --> B1[4개] A1 --> C1[4개] B1 --> D1[2개] B1 --> E1[2개] C1 --> F1[2개] C1 --> G1[2개] end subgraph 나쁜피벗[나쁜 피벗 선택] A2[8개 데이터] --> B2[0개] A2 --> C2[7개] C2 --> D2[0개] C2 --> E2[6개] E2 --> F2[0개] E2 --> G2[5개...] end

    정리하기 📘

    퀵 정렬은 평균적으로 매우 빠르지만, 피벗 선택이 계속 나쁘면 최악의 경우 버블 정렬처럼 느려질 수 있습니다. 그래서 실제로는 "첫 번째 값", "중간 값", "마지막 값" 중 중앙값을 피벗으로 선택하는 등의 기법을 사용합니다.

    🔨 따라하기: 손으로 퀵 정렬 해보기¶

    스마트시티의 8개 교차로 교통량 데이터를 퀵 정렬로 정렬해봅시다.

    원본 데이터: [85, 42, 120, 35, 90, 55, 70, 100] (단위: 대/분)

    Step 1: 첫 번째 분할¶

    피벗 선택: 마지막 값 100을 피벗으로 선택

    분류 작업: - 85 → 100보다 작음 → 왼쪽 - 42 → 100보다 작음 → 왼쪽 - 120 → 100보다 큼 → 오른쪽 - 35 → 100보다 작음 → 왼쪽 - 90 → 100보다 작음 → 왼쪽 - 55 → 100보다 작음 → 왼쪽 - 70 → 100보다 작음 → 왼쪽

    결과: [85, 42, 35, 90, 55, 70] + [100] + [120]

    100과 120은 자기 자리 확정!

    Step 2: 왼쪽 부분 정렬¶

    대상: [85, 42, 35, 90, 55, 70]

    피벗 선택: 마지막 값 70

    분류 결과: [42, 35, 55] + [70] + [85, 90]

    Step 3: 더 작은 부분 정렬¶

    왼쪽 [42, 35, 55] → 피벗 55 → [42, 35] + [55] + []

    오른쪽 [85, 90] → 피벗 90 → [85] + [90] + []

    Step 4: 마지막 분할¶

    [42, 35] → 피벗 35 → [] + [35] + [42]

    Step 5: 결과 합치기¶

    모든 부분이 정렬되었으므로 순서대로 합칩니다:

    [35, 42, 55, 70, 85, 90, 100, 120]

    정렬 완료! 🎉

    flowchart TD A["[85,42,120,35,90,55,70,100]<br>피벗:100"] --> B["[85,42,35,90,55,70]"] A --> C["[100]✓"] A --> D["[120]✓"] B -->|"피벗:70"| E["[42,35,55]"] B --> F["[70]✓"] B --> G["[85,90]"] E -->|"피벗:55"| H["[42,35]"] E --> I["[55]✓"] G -->|"피벗:90"| J["[85]✓"] G --> K["[90]✓"] H -->|"피벗:35"| L["[35]✓"] H --> M["[42]✓"]

    📝 전체 코드¶

    # 퀵 정렬 구현 - 스마트시티 교통량 데이터 정렬

def quick_sort(arr):
    """퀵 정렬 함수"""
    # 기저 조건: 리스트 크기가 1 이하면 이미 정렬됨
    if len(arr) <= 1:
        return arr

    # 피벗 선택 (마지막 요소)
    pivot = arr[-1]

    # 분할: 피벗보다 작은 값, 같은 값, 큰 값으로 나눔
    left = []   # 피벗보다 작은 값
    middle = [] # 피벗과 같은 값
    right = []  # 피벗보다 큰 값

    for value in arr:
        if value < pivot:
            left.append(value)
        elif value > pivot:
            right.append(value)
        else:
            middle.append(value)

    # 재귀 호출로 왼쪽, 오른쪽 정렬 후 합치기
    return quick_sort(left) + middle + quick_sort(right)


# 실행 예제
traffic_data = [85, 42, 120, 35, 90, 55, 70, 100]
print("정렬 전:", traffic_data)

sorted_data = quick_sort(traffic_data)
print("정렬 후:", sorted_data)

    실행 결과: 

    정렬 전: [85, 42, 120, 35, 90, 55, 70, 100]
정렬 후: [35, 42, 55, 70, 85, 90, 100, 120]

    코드 설명¶

    기저 조건 (Base Case): 리스트 크기가 1 이하면 더 이상 정렬할 필요 없음

    피벗 선택: 간단하게 마지막 요소를 피벗으로 사용

    분할: for문으로 각 요소를 피벗과 비교하여 left, middle, right에 분류

    재귀 호출: 왼쪽과 오른쪽을 다시 quick_sort로 정렬

    결합: 정렬된 왼쪽 + 중간(피벗) + 정렬된 오른쪽을 합쳐서 반환

    ✅ 스스로 점검하기¶

    문제 1: 개념 확인 (기본)¶

    다음 중 분할 정복 전략의 단계를 올바른 순서로 나열한 것은?

    A) 정복 → 분할 → 결합

    B) 분할 → 결합 → 정복

    C) 분할 → 정복 → 결합

    D) 결합 → 분할 → 정복

    정답 확인 **정답: C) 분할 → 정복 → 결합** 분할 정복은 먼저 문제를 **분할**하고, 각 부분을 **정복**(해결)한 뒤, 결과를 **결합**합니다.

    문제 2: 분할 결과 예측 (응용)¶

    [50, 30, 80, 20, 60, 10]을 피벗 60으로 분할하면?

    A) 왼쪽: [50, 30, 20, 10] / 오른쪽: [80]

    B) 왼쪽: [50, 30, 80, 20] / 오른쪽: [10]

    C) 왼쪽: [30, 20, 10] / 오른쪽: [50, 80]

    D) 왼쪽: [50, 30, 20, 10] / 오른쪽: [80, 60]

    정답 확인 **정답: A) 왼쪽: [50, 30, 20, 10] / 오른쪽: [80]** 60보다 작은 값: 50, 30, 20, 10 → 왼쪽 60보다 큰 값: 80 → 오른쪽 피벗 60은 중앙에 위치

    문제 3: 성능 이해 (심화)¶

    이미 오름차순으로 정렬된 데이터 [1, 2, 3, 4, 5, 6, 7, 8]에서 항상 마지막 값을 피벗으로 선택하면 어떤 문제가 발생할까요?

    정답 확인 **문제점**: 최악의 성능이 발생합니다. 첫 번째 분할: 피벗 8 → 왼쪽 [1,2,3,4,5,6,7], 오른쪽 [] 두 번째 분할: 피벗 7 → 왼쪽 [1,2,3,4,5,6], 오른쪽 [] 이렇게 매번 한쪽으로만 데이터가 몰려서 n번의 분할이 필요하고, 버블 정렬과 비슷한 O(n²) 성능이 됩니다. **해결책**: 첫 번째, 중간, 마지막 값 중 중앙값을 피벗으로 선택하는 방법 등을 사용합니다.
