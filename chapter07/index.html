    🌊 1차시·2차시 통합 정리 — 문제 분해에서 모델링까지¶

    Part 2: 문제 분해와 모델링 — 복잡한 문제를 쪼개고 구조화하기

    🎯 이 장에서 배우는 것¶

    • 문제 분해, 추상화, 모델링의 개념을 구분하여 정확하게 설명할 수 있다
    • 새로운 사회문제에 문제 분해 → 추상화 → 모델링 3단계를 적용할 수 있다
    • 다음 차시(정렬 알고리즘)와의 연결 고리를 이해하고 설명할 수 있다

    📚 핵심 개념 정리¶

    개념 1: 문제 분해 (Decomposition)¶

    비유로 시작: 문제 분해는 마치 큰 피자를 조각으로 나누는 것과 같아요. 피자 한 판을 통째로 먹기 어렵지만, 조각으로 나누면 한 조각씩 먹을 수 있죠!

    정확한 정의: 복잡한 문제를 해결하기 쉬운 작은 문제들로 나누는 작업입니다.

    핵심 포인트 - 큰 문제 → 작은 문제들로 분리 - 각 조각은 독립적으로 해결 가능 - "무엇을 해야 하는가?"에 답하는 단계

    개념 2: 추상화 (Abstraction)¶

    비유로 시작: 추상화는 마치 지하철 노선도와 같아요. 실제 지하철 터널의 구불구불한 모양, 역 건물의 생김새는 생략하고, 오직 역 이름과 연결 순서만 남기죠!

    정확한 정의: 복잡한 문제에서 불필요한 요소를 제거하고 핵심 요소만 남기는 과정입니다.

    핵심 포인트 - 불필요한 정보 제거 - 반드시 필요한 핵심만 추출 - "무엇이 중요한가?"에 답하는 단계

    개념 3: 모델링 (Modeling)¶

    비유로 시작: 모델링은 마치 설계도 그리기와 같아요. 건축가가 집을 짓기 전 도면을 그리듯, 추상화한 요소들의 관계를 눈에 보이게 표현하는 거예요!

    정확한 정의: 추상화된 핵심 요소들 간의 관계를 글, 그림, 수식, 표 등으로 구조화하여 표현하는 것입니다.

    핵심 포인트 - 요소들 사이의 관계를 정의 - 이해하기 쉬운 형태로 시각화 - "어떻게 연결되는가?"에 답하는 단계

    🔄 세 개념의 흐름¶

    flowchart LR A[복잡한 문제] --> B[문제 분해] B --> C[추상화] C --> D[모델링] D --> E[해결 가능한 형태] B -.-> B1["작은 문제로 나누기"] C -.-> C1["핵심만 추출하기"] D -.-> D1["관계를 구조화하기"]

    💡 알아보기: 세 단계는 항상 순서대로 진행됩니다. 문제를 먼저 쪼개고(분해), 핵심을 골라내고(추상화), 관계를 정리합니다(모델링).

    🔨 따라하기: 교통사고 다발 지역 분석¶

    실제 사회문제에 3단계를 적용해 봅시다!

    상황: "우리 동네 교통사고를 줄이고 싶어요"

    Step 1: 문제 분해하기¶

    큰 문제를 작은 질문들로 나눕니다.

    원래 문제: "교통사고를 줄이자"

↓ 문제 분해 ↓

작은 문제 1: 어디서 사고가 많이 나는가?
작은 문제 2: 언제 사고가 많이 나는가?
작은 문제 3: 왜 그 장소에서 사고가 나는가?
작은 문제 4: 어떤 해결책이 있는가?

    생각해보기 🤔: 하나의 큰 문제가 4개의 작은 질문으로 나뉘었어요. 이제 각각을 따로 해결할 수 있겠죠?

    Step 2: 추상화하기¶

    각 문제에서 핵심 요소만 추출합니다.

    [제거할 것들]
- 도로의 풍경, 날씨 변화
- 운전자의 기분, 차량 색상
- 주변 건물의 모양

[남길 핵심 요소]
✓ 사고 발생 위치 (위도, 경도)
✓ 사고 발생 시간 (시간대)
✓ 사고 유형 (충돌, 추돌 등)
✓ 도로 특성 (신호등 유무, 횡단보도)

    Step 3: 모델링하기¶

    핵심 요소들의 관계를 구조화합니다.

    코드: 

    # 교통사고 데이터 모델링
accident_data = {
    "위치": "서울시 강남구 삼성동 교차로",
    "시간대": "오후 6시~8시",
    "사고유형": "차량 충돌",
    "도로특성": {
        "신호등": True,
        "횡단보도": True,
        "차선수": 4
    }
}

# 모델 출력
print("=== 사고 다발 지역 분석 모델 ===")
print(f"위치: {accident_data['위치']}")
print(f"위험 시간대: {accident_data['시간대']}")
print(f"주요 사고 유형: {accident_data['사고유형']}")

    실행 결과: 

    === 사고 다발 지역 분석 모델 ===
위치: 서울시 강남구 삼성동 교차로
위험 시간대: 오후 6시~8시
주요 사고 유형: 차량 충돌

    Step 4: 여러 지역 데이터 확장¶

    코드: 

    # 여러 지역의 사고 데이터
accidents = [
    {"지역": "A교차로", "사고건수": 15, "시간대": "저녁"},
    {"지역": "B골목", "사고건수": 8, "시간대": "아침"},
    {"지역": "C횡단보도", "사고건수": 22, "시간대": "저녁"},
    {"지역": "D사거리", "사고건수": 11, "시간대": "점심"}
]

# 사고 건수 출력
print("=== 지역별 사고 현황 ===")
for data in accidents:
    print(f"{data['지역']}: {data['사고건수']}건 ({data['시간대']} 집중)")

    실행 결과: 

    === 지역별 사고 현황 ===
A교차로: 15건 (저녁 집중)
B골목: 8건 (아침 집중)
C횡단보도: 22건 (저녁 집중)
D사거리: 11건 (점심 집중)

    Step 5: 데이터 정렬의 필요성 발견¶

    코드: 

    # 현재 데이터는 정리되지 않은 상태
accidents = [
    {"지역": "A교차로", "사고건수": 15},
    {"지역": "B골목", "사고건수": 8},
    {"지역": "C횡단보도", "사고건수": 22},
    {"지역": "D사거리", "사고건수": 11}
]

print("정리 전: 어디가 가장 위험한지 한눈에 보이지 않음")
for data in accidents:
    print(f"  {data['지역']}: {data['사고건수']}건")

print("\n→ 사고 건수 순으로 정렬하면 우선순위가 명확해짐!")
print("→ 이것이 다음 차시에서 배울 '정렬 알고리즘'의 역할!")

    실행 결과: 

    정리 전: 어디가 가장 위험한지 한눈에 보이지 않음
  A교차로: 15건
  B골목: 8건
  C횡단보도: 22건
  D사거리: 11건

→ 사고 건수 순으로 정렬하면 우선순위가 명확해짐!
→ 이것이 다음 차시에서 배울 '정렬 알고리즘'의 역할!

    📝 전체 코드¶

    # === 1차시·2차시 통합 실습: 교통사고 다발 지역 분석 ===

# [Step 1~2] 문제 분해 + 추상화 결과를 데이터로 표현
accidents = [
    {"지역": "A교차로", "사고건수": 15, "시간대": "저녁"},
    {"지역": "B골목", "사고건수": 8, "시간대": "아침"},
    {"지역": "C횡단보도", "사고건수": 22, "시간대": "저녁"},
    {"지역": "D사거리", "사고건수": 11, "시간대": "점심"}
]

# [Step 3] 모델링: 데이터 출력
print("=== 교통사고 다발 지역 분석 결과 ===\n")

for data in accidents:
    print(f"📍 {data['지역']}")
    print(f"   사고 건수: {data['사고건수']}건")
    print(f"   위험 시간대: {data['시간대']}")
    print()

# [Step 4] 다음 단계 예고: 정렬의 필요성
print("💡 다음 과제: 사고 건수 순으로 정렬하여 우선순위 파악하기")

    ⚠️ 주의할 점¶

    1. 세 단계의 순서를 지키세요 - 분해 → 추상화 → 모델링 순서가 바뀌면 안 됩니다 - 문제를 나누지 않고 바로 모델링하면 중요한 요소를 놓칠 수 있어요

    2. 추상화에서 "너무 많이" 버리지 마세요 - 핵심이 아닌 것만 버려야 합니다 - 예: 사고 위치는 핵심 → 반드시 남기기!

    ✅ 점검하기¶

    1. 문제 분해, 추상화, 모델링을 올바른 순서로 나열하면?

    정답 확인 **문제 분해 → 추상화 → 모델링** 분해로 문제를 쪼개고, 추상화로 핵심을 추출하고, 모델링으로 관계를 구조화합니다.

    2. "지하철 노선도가 실제 지리를 단순화한 것"은 어떤 개념의 예시인가요?

    정답 확인 **추상화** 불필요한 요소(실제 터널 모양, 거리 비율)를 제거하고 핵심(역 이름, 연결 순서)만 남긴 것입니다.

    3. 모델링 결과로 얻은 데이터가 정리되지 않으면 어떤 문제가 생길까요?

    정답 확인 **우선순위 파악이 어렵습니다** 예: 사고 건수가 뒤죽박죽이면 어디가 가장 위험한지 한눈에 알 수 없습니다. 이를 해결하는 것이 **정렬 알고리즘**입니다!

    flowchart LR A[이번 차시] --> B[다음 차시] A -.-> A1["문제 분해<br>추상화<br>모델링"] B -.-> B1["정렬 알고리즘<br>버블 정렬<br>삽입 정렬"] C[연결 고리] --> D["모델링 결과 데이터를<br>정렬해서 정리하기!"]

    🚀 다음 시간 예고: 오늘 만든 사고 데이터를 "사고 건수가 많은 순서"로 정렬해 볼 거예요. 버블 정렬과 삽입 정렬, 두 가지 방법으로 같은 결과를 만들어 보며 알고리즘의 효율성을 비교합니다!

    📌 정리하기: 이번 시간에는 1차시(문제 분해)와 2차시(추상화·모델링)의 핵심 개념을 복습하고, 교통사고 분석이라는 새로운 문제에 3단계를 적용해 보았습니다. 모델링으로 얻은 데이터를 효과적으로 활용하려면 정렬이 필요하다는 것을 발견했고, 이것이 다음 차시의 주제입니다!
