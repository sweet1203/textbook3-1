    🚑 응급실의 선택 — 문제 분해란 무엇인가¶

    Part 2: 문제 분해와 모델링 — 복잡한 문제를 쪼개고 구조화하기

    🎯 이 장에서 배우는 것¶

    이 장을 마치면 다음을 할 수 있습니다:

    • 문제 분해의 정의를 설명하고, 복잡한 문제를 작은 문제로 나누는 방법을 제시할 수 있다
    • 응급의료 환자 분류(트리아지) 상황에서 문제 분해 과정을 단계별로 수행할 수 있다
    • 문제 분해가 왜 효율적인 문제 해결의 출발점인지 근거를 들어 설명할 수 있다
    • 파이썬으로 간단한 문제 분해 결과를 코드로 표현할 수 있다

    💡 왜 이걸 배우나요?¶

    생각해보기 🤔

    금요일 저녁 8시, 응급실에 동시에 10명의 환자가 도착했습니다. - 교통사고로 의식을 잃은 환자 - 심한 복통을 호소하는 환자
    - 손가락에 작은 상처가 난 환자 - 갑자기 숨쉬기 어려워하는 환자

    의료진이 한 명뿐이라면, 누구를 먼저 치료해야 할까요?

    이 질문에 답하려면 "10명을 동시에 치료하는 것"이라는 불가능한 문제를 더 작고 해결 가능한 문제들로 나눠야 합니다.

    실제로 응급실에서는 트리아지(Triage)라는 시스템을 사용합니다. 프랑스어로 '분류하다'라는 뜻인 이 시스템은 복잡한 상황을 체계적으로 분해하여 해결하는 대표적인 예입니다.

    문제 분해는 프로그래밍의 시작점이자, 일상생활에서도 매일 사용하는 사고방식입니다. 이번 장에서는 이 강력한 도구를 제대로 익혀봅시다.

    📚 핵심 개념¶

    개념 1: 문제 분해(Decomposition)란?¶

    🍕 비유로 시작하기¶

    피자 한 판을 혼자 한 입에 먹을 수 있나요? 불가능하죠. 하지만 8조각으로 자르면 한 조각씩 먹을 수 있습니다.

    문제 분해도 마찬가지입니다. 거대하고 복잡한 문제를 먹기 좋은 크기로 자르는 것입니다.

    📖 정확한 정의¶

    문제 분해(Decomposition)

    복잡한 문제를 해결하기 쉬운 작은 문제들로 나누는 작업입니다. 분해된 각 문제는 독립적으로 해결할 수 있으며, 이들을 합치면 전체 문제의 해답이 됩니다.

    ✨ 예시로 확인하기¶

    "아침에 학교 가기"라는 문제를 분해해봅시다:

    graph TD A[아침에 학교 가기] --> B[1. 일어나기] A --> C[2. 준비하기] A --> D[3. 이동하기] C --> C1[씻기] C --> C2[옷 입기] C --> C3[아침 먹기] C --> C4[가방 챙기기] D --> D1[집 나서기] D --> D2[교통수단 이용] D --> D3[학교 도착]

    복잡해 보이던 "학교 가기"가 9개의 작은 행동으로 분해되었습니다. 각각은 쉽게 실행할 수 있죠!

    개념 2: 트리아지 — 응급실의 문제 분해¶

    🏥 비유로 시작하기¶

    상상해보세요. 여러분이 음식점 매니저입니다. 손님 100명이 동시에 몰려왔을 때, "100명 모두 동시에 서빙하자!"는 불가능합니다. 대신 "누가 가장 급한가?"를 기준으로 순서를 정하겠죠.

    응급실도 똑같습니다.

    📖 정확한 정의¶

    트리아지(Triage)

    응급 환자를 중증도에 따라 분류하여 치료 우선순위를 결정하는 시스템입니다. 제한된 의료 자원을 가장 효과적으로 사용하기 위한 문제 분해의 실제 적용 사례입니다.

    ✨ 트리아지의 5단계 분류¶

    graph LR subgraph 긴급도 높음 A[1단계: 즉시<br/>심정지, 쇼크] B[2단계: 긴급<br/>심한 출혈, 호흡곤란] end subgraph 긴급도 중간 C[3단계: 준긴급<br/>복통, 고열] end subgraph 긴급도 낮음 D[4단계: 비긴급<br/>경미한 상처] E[5단계: 지연가능<br/>가벼운 감기] end A --> B --> C --> D --> E

    핵심 통찰: 트리아지는 "누구를 치료할까?"라는 복잡한 문제를 다음과 같이 분해합니다:

    • 하위 문제 1: 환자의 증상은 무엇인가?
    • 하위 문제 2: 생명에 즉각적 위험이 있는가?
    • 하위 문제 3: 치료가 지연되면 상태가 악화되는가?

    개념 3: 좋은 문제 분해의 조건¶

    🧩 비유로 시작하기¶

    퍼즐 조각을 생각해보세요. 좋은 퍼즐은: - 각 조각이 명확한 모양을 가집니다 - 조각들이 서로 겹치지 않습니다 - 모든 조각을 맞추면 완전한 그림이 됩니다

    문제 분해도 마찬가지입니다!

    📖 좋은 분해의 3가지 조건¶

    조건 1: 독립성 — 각 하위 문제는 다른 문제와 무관하게 해결 가능해야 합니다

    조건 2: 완전성 — 모든 하위 문제를 해결하면 원래 문제가 해결되어야 합니다

    조건 3: 적절한 크기 — 하위 문제가 바로 해결할 수 있을 만큼 작아야 합니다

    ✨ 잘못된 분해 vs 올바른 분해¶

    "저녁 식사 준비"를 분해한다면:

    graph TD subgraph 잘못된_분해 X1[재료 사기] --> X2[요리하기] --> X3[맛있게 먹기] end subgraph 올바른_분해 Y1[메뉴 정하기] Y2[필요한 재료 목록 작성] Y3[재료 구매하기] Y4[재료 손질하기] Y5[조리하기] Y6[그릇에 담기] end

    잘못된 분해의 "요리하기"는 여전히 복잡합니다. 올바른 분해는 각 단계가 구체적이고 실행 가능합니다.

    개념 4: 문제 분해와 프로그래밍의 관계¶

    💻 비유로 시작하기¶

    레고로 집을 만든다고 상상해보세요. 처음부터 "집을 만들어!"라고 하면 막막하지만, 설명서는 이렇게 안내합니다: 1. 바닥 만들기 (단계 1-10) 2. 벽 만들기 (단계 11-25) 3. 지붕 만들기 (단계 26-35)

    프로그래밍도 복잡한 프로그램을 작은 기능(함수)으로 분해합니다.

    📖 프로그래밍에서의 문제 분해¶

    정리하기 📋

    프로그래밍에서 문제 분해는 함수(function)로 구현됩니다. - 각 함수는 하나의 작은 문제를 해결합니다 - 함수들을 조합하면 전체 프로그램이 완성됩니다 - 이렇게 하면 코드 수정과 오류 찾기가 쉬워집니다

    🔨 따라하기: 응급실 환자 분류 시스템 만들기¶

    응급실의 트리아지 시스템을 파이썬으로 구현해봅시다. 복잡해 보이지만, 문제 분해를 통해 단계별로 접근하면 충분히 만들 수 있습니다!

    Step 1: 전체 문제 파악하기¶

    해결할 문제: "여러 환자의 정보를 입력받아 치료 우선순위를 결정하는 프로그램"

    이 문제를 분해하면:

    graph TD A[환자 분류 시스템] --> B[1. 환자 정보 입력받기] A --> C[2. 긴급도 판단하기] A --> D[3. 우선순위 결정하기] A --> E[4. 결과 출력하기]

    Step 2: 첫 번째 하위 문제 — 환자 정보 입력받기¶

    먼저 환자의 기본 정보를 입력받는 코드를 작성합니다:

    # Step 2: 환자 정보 입력받기
def get_patient_info():
    """환자 정보를 입력받아 반환하는 함수"""
    name = input("환자 이름을 입력하세요: ")
    symptom = input("주요 증상을 입력하세요: ")
    pain_level = int(input("통증 수준(1-10): "))

    return name, symptom, pain_level

# 테스트 실행
patient = get_patient_info()
print(f"입력된 정보: {patient}")

    실행 결과 예시: 

    환자 이름을 입력하세요: 김철수
주요 증상을 입력하세요: 복통
통증 수준(1-10): 7
입력된 정보: ('김철수', '복통', 7)

    Step 3: 두 번째 하위 문제 — 긴급도 판단하기¶

    증상과 통증 수준을 기반으로 긴급도를 판단합니다:

    # Step 3: 긴급도 판단하기
def determine_urgency(symptom, pain_level):
    """증상과 통증 수준으로 긴급도를 판단하는 함수"""

    # 즉시 치료가 필요한 증상 목록
    critical_symptoms = ["의식불명", "심정지", "대량출혈", "호흡곤란"]

    # 긴급도 판단 로직
    if symptom in critical_symptoms:
        return 1  # 1단계: 즉시
    elif pain_level >= 8:
        return 2  # 2단계: 긴급
    elif pain_level >= 5:
        return 3  # 3단계: 준긴급
    elif pain_level >= 3:
        return 4  # 4단계: 비긴급
    else:
        return 5  # 5단계: 지연가능

# 테스트

    # Step 6: 여러 환자 처리 (확장 버전)
def process_multiple_patients():
    """여러 환자를 처리하고 우선순위대로 정렬"""
    patients = []

    while True:
        add_more = input("\n환자를 등록하시겠습니까? (y/n): ")
        if add_more.lower() != 'y':
            break

        name, symptom, pain_level = get_patient_info()
        urgency = determine_urgency(symptom, pain_level)
        patients.append({
            'name': name,
            'symptom': symptom,
            'pain': pain_level,
            'urgency': urgency
        })

    # 긴급도 순으로 정렬 (숫자가 작을수록 긴급)
    patients.sort(key=lambda x: x['urgency'])

    # 치료 순서 출력
    print("\n" + "=" * 40)
    print("📋 치료 우선순위 목록")
    print("=" * 40)

    for i, patient in enumerate(patients, 1):
        message = get_priority_message(patient['urgency'])
        print(f"{i}. {patient['name']} - {message}")

    확인 문제 1: 개념 이해¶

    "피자 주문 과정"을 올바르게 분해한 순서는?

    보기: - (가) 결제하기 - (나) 메뉴 선택하기 - (다) 배달 받기 - (라) 앱 실행하기 - (마) 배달 주소 입력하기

    1. (가) → (나) → (다) → (라) → (마)
    2. (라) → (나) → (마) → (가) → (다)
    3. (나) → (라) → (가) → (마) → (다)
    4. (라) → (마) → (나) → (가) → (다)
    정답 확인 **정답: 2번** 올바른 순서: 1. (라) 앱 실행하기 2. (나) 메뉴 선택하기 3. (마) 배달 주소 입력하기 4. (가) 결제하기 5. (다) 배달 받기 문제 분해는 **논리적인 실행 순서**를 고려해야 합니다!
